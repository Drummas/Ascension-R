# The presets as steps: Smooth, Balanced and Ultra, in Faithful's place (2026-11-25)

Faithful ("everything drawn as on the PS3") had every game patch off, MLAA included. MLAA's work is a copy of the frame
in main memory that this port never shows (note 2026-11-23-bloom-spu-mlaa.md), so Faithful paid about 5% for nothing,
and it left the picture at whatever the Graphics tab had. Ultra takes its place as the most the port can draw.

## What a preset sets now

A preset was the game patches it switches on. It now also gives the picture settings a value (`Preset.set` in
`port/launcher.cpp`), the same ones in all three, as steps; `preset_now` matches both, so a preset shows as chosen only
while all of them hold, and anything else is "Custom setup".

| | Smooth | Balanced | Ultra |
|---|---|---|---|
| patches on | Disable MLAA, Disable motion blur, Disable shadows | Disable MLAA, Disable motion blur | Disable MLAA, Disable mesh trimming (keeps the thin triangles above 720p) |
| internal resolution, scaling | 720p, AMD FSR 1, sharpening high | 1080p, AMD FSR 1, sharpening medium | the window's size, bilinear |
| frame generation | off | off | off |
| anti-aliasing, filtering | SMAA, 16x | SMAA, 16x | SMAA, 16x |
| shadow resolution, effects resolution, ambient occlusion | 1, game, off | 2, internal, on | 4, internal, high |
| debanding, CAS | off, off | on, off | on, low |

MLAA is off in all: its picture is never shown, only its cost. None uses AMD FSR or frame generation: both take the
game's frame order without MLAA, where the bloom and the motion blur never reach the picture; AMD FSR 1 upscales the
finished frame and keeps them. Colour vibrance, contrast, field of view, HDR and the display settings stay the player's.

Smooth is this port's defaults, so a first start shows it: Scaling's default is now AMD FSR 1 (was bilinear),
Anti-aliasing's SMAA (was off) and Anisotropic filtering's 16x (was the game's). A settings file written before keeps
its own values. `recomplauncher.json`'s preset choice and defaults match.

## Measured

i5-12400F, RX 6700 XT, 1080p borderless, one run each unless said.

The bench route on `build\bench-hdd0` (Kratos at the gate, one enemy; vibrance and contrast off):

| | median flips/s | GPU busy |
|---|---|---|
| Smooth | 59.9 (the 60 the game runs at) | 67-70% |
| Balanced | 55.3 | 69% |
| Ultra | 52.4 | 73% |

A heavier fight (several enemies, from the saves in `gamedata`, two runs each): Smooth with this PC's own scaling (AMD FSR
from 1.5x) 56.5 and 59.7, Ultra 40.4 and 37.9, at the same GPU load. The game's own dynamic shadows and motion blur are
CPU and SPU work, and that is where Balanced's and Ultra's frames go; the extras (shadow maps, effects at full size,
ambient occlusion) add their own on a weaker GPU or at 1440p and 4K (notes 2026-11-24 and 2026-11-25: about 0.6, 0.6
and 1 to 2 ms at 4K).

## Ambient occlusion On drew stripes

Balanced's first screenshots had horizontal stripes on the floor before Kratos. One run with ambient occlusion off had
none, one with 1x shadows still had them: ambient occlusion On, drawn at half the render's size. A half-size pixel's
middle is the edge of two of the render's, so the depth read there was one pixel's, put back into the world half a
pixel away; on a floor seen at a low angle the depth changes fast from row to row and the error took turns: stripes.
High, at full size, was clean. Every point is now taken at the middle of the render's pixel its depth comes from
(`mid`, `wpat` in the shaders, ps3recomp `rsx_d3d12_backend.c`); the same floor with On is clean, the occlusion alone
(`D3D12_AO_DEBUG=1`) shows only the contact shade, and Balanced runs at 54.9 against 55.3.

Changing a setting that shapes the shaders (shadow resolution among them) shows "Pixel shaders partly built" on the
ready check until **Build** or the first session builds the rest, as before.
